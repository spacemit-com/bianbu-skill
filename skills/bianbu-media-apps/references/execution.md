# 执行与证据

本文件仅适用于用户明确要求的真实 GUI 验收。默认 CLI 功能验证以 [cli.md](cli.md) 为准，不要求本文件的鼠标、截图或听感证据。

播放器通用证据指南。mpv 用原始 cases.json；Totem/VLC 用各自适配基线。下文提到 mpv 专属属性/IPC 时，仅可用于 mpv；其他播放器使用其 GUI 可见状态、时间/音量显示或已确认的只读接口采样，不运行 mpv 作为旁路来“验证”它们。Snapshot 仅复用本文件的结果结构，其观察项定义见 snapshot.md。

## 前置检查

- 记录 `hostname`、目标应用实际安装版本、当前图形会话、真实 GUI 工具名称与能力。mpv 可读取 `mpv --version`；其他应用从安装包元数据或自身已确认的版本入口获取。先确认工具支持板端截图及真实输入事件；只读 IPC 不属于 GUI 操作能力。
- 记录既有 mpv 窗口/PID，区分本次创建的对象。Wayland 下不要假定 xdotool 可以操控原生窗口，也不要为此退出用户桌面。
- 列出当前音频路由、静音及音量。无音频回采/人工听感证据时，不给“音画同步”“实际音量改变”打 PASS。播放属性 `avsync` 只能辅助说明调度状态。
- 选择带运动画面、音轨且时长足够 Seek 的本地视频。容器用例需要 MP4、MKV、AVI、MOV、WebM、FLV 各一个；用 ffprobe 记录真实容器、编解码、分辨率、帧率、时长、大小和 SHA-256。扩展名不等于容器，也不等于全部编解码覆盖。找不到的素材对应 BLOCKED。可在本次目录用已安装 FFmpeg 制作小型、有限时长素材，记录命令，不安装新包，不覆盖源文件。
- 用含可对应视觉/音频事件的素材测音画同步。仅测试色条+独立正弦波不足以证明同步。没有同步样本或验证方法，编号 3 的同步观察项为 BLOCKED；记录视频播放子步骤的已完成情况。

## GUI 动作与辅助观测

`method` 必须与基线允许的动作类型相符：

| method | 必须实际发生的行为 |
|---|---|
| desktop-launch | 启动目标应用并观察桌面窗口；可由桌面启动器或可证明是图形窗口的启动命令触发 |
| open-with | 文件管理器中选中媒体，使用“打开方式”选择本项目标播放器 |
| drag-drop | 将文件从文件管理器真实拖到本项目标播放器窗口 |
| click | 点击目标播放器的实际可见暂停/继续或其他本步骤控件；mpv 使用其 OSC，其他应用使用自身控件 |
| keyboard | 板端 OS 输入事件送达目标窗口，并记录键名/绑定；IPC keypress 不满足 |
| progress-drag | 在目标播放器实际进度条上拖动 |
| window-close | 使用窗口关闭控件或窗口管理器正常关闭该窗口 |
| gui-play | 使用图形界面加载/启动本项媒体；轨迹必须说明具体入口 |
| inspect-bindings | 只读查询当前 input-bindings 或配置并存证；用于编号 6 选择实际音量键，不证明调音量动作完成 |

操作轨迹可为工具返回的动作日志、会话导出或屏幕录制；不能用一句自述代替真实动作记录。截图不应包含无关应用信息。每个证据应标明采集时刻、用途、工具或人工观察来源。

## 观察项

- `window_visible`：板端截图显示本次目标应用窗口；不能只以进程存在为据。
- `video_advances`：时间序列截图/录屏证明画面更新，同时保存 IPC time-pos 或可见播放时间的前后值。视频静止帧测试不能满足运动视频判断。
- `window_closed`：关闭后的板端窗口状态及本次 PID 退出/窗口消失记录；不关闭其他 mpv 实例。
- `paused` / `resumed`：先后图像与 time-pos 序列；暂停后时间稳定至少 1 秒，恢复后至少 1 秒内继续推进。阈值/采样值写入观察内容。
- `seek_valid`：实际按键/拖条后的时间跳转及视频恢复证据；需测试前后方向，保留每次目标与实际位置。不得以调用 `seek` 命令成功代替 GUI 动作。
- `volume_binding_valid`：核对当前 mpv 绑定，选出实际增/减音量键。用户已授权以 mpv 行为为准；保留原表 ↑↓，在实际观察中记录选用键名及其 volume 命令，无需因键位差异阻塞。没有可用键盘映射或不能读取/确认绑定时才说明阻塞。
- `volume_control_identified`：Totem/VLC 适配用例核对目标程序的实际音量控件或键位，保存该控件截图或绑定记录；不能引用 mpv 的绑定作为证明。
- `volume_valid`：真实键位/控件操作后的目标应用音量值和实际音频电平/人工听感变化；静音输出、null 音频或仅属性变化不能通过。
- `fullscreen_on` / `fullscreen_off`：目标显示器上的全屏及退出截图、窗口状态，两个方向均验证。只有 fullscreen 属性为 true 不足。
- `av_sync_valid`：带对齐事件的屏幕/音频同步录制或明确的人工同步观察；记录方法、事件时差和判据。未提供判据时，可使用预先声明的本次暂定容差 ±100 ms，并在报告注明非原表给定要求；不能以事后放宽阈值获得通过。
- `container_matches`：ffprobe 信息表明实际容器匹配原项，记录多重名称的解析依据（例如 MOV/MP4 共用解复用器，需结合 brands/封装证据）。

基线中的 `evidence_kinds` 表示所需证据类型组：每组至少有一个匹配类型，且所有组都满足。不同观察可引用同一个真实录屏，需在说明中给出对应时间段。

## 结果填写格式

`init` 生成固定用例和步骤。只填记录字段，不改 id/title/priority/source_step。以下片段仅说明结构，不是本次测试结果，不得原样当成事实：

```json
{
  "status": "BLOCKED",
  "actual_result": "当前只有 SSH，无板端 GUI 点击/截图工具。",
  "reason_code": "NO_GUI_TOOL"
}
```

步骤 observations 的结构为 `{"key":"window_visible","actual":"具体观察","evidence":["ev-id"]}`。证据顶层结构为 `{"id":"ev-id","path":"evidence/实际文件.png","kind":"screenshot","captured_at":"ISO 8601 带时区时间","producer":"实际采集工具","description":"本证据用途"}`。PASS 步骤另需 `action_evidence`，指向 `gui_trace` 或 `screen_recording`，证明指定的动作发生。单张截图不能独立证明拖拽或点击全过程。

环境字段中的 `media` 应为实际素材元数据列表，每项包含 path/container/video_codec/audio_codec/width/height/fps/duration/sha256；无素材时填空列表并阻塞相关项目。

## 报告语义

报告主表与所选基线逐项对应；每步写实际观察而非复制“预期结果”。mpv 为原表，Totem/VLC 为适配，Snapshot 为新增，不混淆来源。所有 FAIL、BLOCKED、NOT_RUN 可追溯。优先级不直接等同缺陷严重程度。补充诊断另写附录，不并入基线通过率。校验器无法判断录屏内容是否真实或截图是否证明预期，需要审阅证据；其成功不能被描述为桌面验收成功。
