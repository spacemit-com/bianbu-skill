# K3 RISC-V 兼容性指南

本指南只用于辅助问题分类，不代表可以进行未经验证的推测性修改。

| 信号 | 类别 | 推荐处理方式 |
|---|---|---|
| `immintrin.h`、`x86intrin.h`、`__m128*`、`_mm_*`、`-msse*`、`-mavx*` | x86 SIMD | 保留受架构条件保护的 x86 路径；优先启用现有标量实现或增加经过测试的可移植回退。只有在工具链与硬件能力均已验证时才增加 RVV。 |
| `arm_neon.h`、`uint8x16_t`、`vld1q_*`、`__aarch64__`、`-march=armv8*` | ARM SIMD | 保留受架构条件保护的 NEON 路径；使用标量回退或经过验证的 RVV 等价实现。不得仅按 intrinsic 名称做机械映射。 |
| 包含 x86/ARM 寄存器的内联汇编 | 汇编 | 用架构条件隔离；先用可移植 C/C++ 表达其语义，并验证屏障、标志位和 clobber。 |
| 硬编码的 `x86_64`、`amd64`、`aarch64`、`arm64` 允许列表 | 平台识别 | 补充 `riscv64`/`riscv`，不得把未知架构默认当作 x86；构建期与运行时识别必须一致。 |
| `-march=native` 或继承自宿主机的编译参数 | 构建配置 | 改用明确的目标参数，或在正确性基线中省略；不得据此假定 RVV 可用。 |
| 未对齐的类型化指针解引用 | 对齐/别名 | 使用 `memcpy` 或逐字节访问，并保持原有字节序与序列化格式。 |
| 围绕 `long`、指针或原子类型的位宽假设 | ABI/数据模型 | K3 为 RV64/LP64；二进制边界使用固定宽度整数，并核对格式化字符串。 |
| 编译器原子内建或手写内存屏障 | 并发 | 优先使用 C11/C++ 原子；核对内存序语义，不得用更弱的屏障替代。 |
| riscv64 上缺少软件包 | 依赖 | 替换前先检查能否从源码构建或使用兼容版本，并记录来源与许可证。 |
| 可执行文件构建成功但崩溃或出现非法指令 | 运行时 ISA | 检查 ELF 属性和实际生成指令；启用优化路径前确认运行时 ISA 扩展。 |

## K3 验证命令

```sh
uname -m
cc -dM -E - </dev/null | grep '^#define __riscv'
file path/to/binary
readelf -h path/to/binary
readelf -A path/to/binary
```

正确性优先的移植中，通过上游测试的标量实现优于未经验证的向量重写。性能优化机会应单独记录，不得与正确性基线混为一谈。

## 当前路径与文档漂移

按以下证据确定当前受支持的构建路径：当前 CI 实际执行的配置、当前树中的构建文件、发布打包配置、README。若 README 引用的 Makefile、目标或脚本已从当前树删除，应记录为文档漂移，不从历史提交恢复它来制造新的移植范围。只有用户明确要求或发布契约仍包含该入口时，才单独恢复并验证。

若当前基线已经构建和测试通过，正确性移植应停止。平台识别确有错误、下游配置受到影响时可以做最小修复；手写 RVV、兼容层和基准重写属于独立性能或功能任务。

## 从正确性到性能的决策门

1. 先让未修改基线失败，并确认第一个根因。
2. 优先寻找项目已有标量路径；没有时，只实现项目实际使用的 intrinsic 语义。
3. 官方测试通过后，用相同参数重复计时至少三次。
4. 只有热点仍显著、手写 RVV 有可验证收益且差分测试覆盖边界语义时，才升级为显式 RVV。
5. 用 `objdump`/`readelf` 证明 ISA 路径，但不得把向量指令数量当作性能指标。
6. 保留差分测试源码、固定随机种子、编译参数和全部工作负载结果；任一重要分布出现明显回退时，优先运行时选择标量或不交付该优化。

## Harness 执行注意事项

- 不跨 Shell 调用依赖 `/tmp`；使用项目内 `.riscv-porter/scratch/`。
- 大型生成 C/C++ 文件可能让优化构建超过前台工具时限。使用后台任务并监控日志，不要反复清洁重建。
- 对文件先 `rg -n` 定位再读取相关区段；同一文件没有新问题时不要重复读取。
- 可选 benchmark、联网依赖和额外语言绑定与官方测试分开记录，单项默认预算 120 秒。
