# v2 报告与选择规则

模型行与测量配置分层保存。模型行保存来源、配方、包信息、全部 attempts、所选 run 和选择理由；测量配置保存 metric、unit、baseline、三次样本、中位数、差异、统一退化、命令、日志、输入 SHA256，以及存在时的 initial 初测。

结果选择只允许以下规则：首次稳定结果作为当前结果；退化候选必须自动复测，复测结果成为当前结果，同时嵌入 initial；两次均退化才标 `confirmed_regression`。量化不符优先为 `baseline_mismatch`。明显快于官方值也标 `review_required`，因为可能存在方法或环境不一致。软件包版本差异单独保存在 comparability；它不覆盖已确认的性能告警。

覆盖公式：适用模型数 = 测量终态 + 策略过滤 + 用户跳过 + 大小跳过 + 有证据的失败/阻塞。`blocked_recipe_review` 表示官方 commit 已改变，不能用旧专用配方。音频模型始终保留在覆盖清单中并标记 `skipped_policy`，不检查包大小，不下载、解包或测试。

最终报告先列确认告警及初测/复测，再列 review、环境/基准不一致、失败和完整覆盖表。>5GB 项逐项给出 URL、已核实大小、模型 ID 和单模型命令。没有成功测量时明确说明无性能结论。

审计失败时不发布“完成”结论。保留 `audit.json`、`cache-ledger.json`、run 元数据和原始日志。
